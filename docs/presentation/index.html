BCrypt Password Hashing & Institutional Domain Gating

Institutional Security
Institutional Domain Regex Constraint
^[A-Za-z0-9._%+-]+@tkmce\.ac\.in$

Enforced at three distinct architectural layers:

1. In Swing GUI input validation.

2. In AuthService before database query execution.

Three-Layer Domain Defense
jBCrypt Salted Password Architecture

• Work Factor 10 (2^10 Rounds): Provides optimal balance between security against brute-force attacks and fast login times (~80 ms).

• Unique Cryptographic Salt: Each password hash generates a unique 128-bit salt, neutralizing rainbow table attacks.

• Constant-Time Equality: Password verification uses constant-time string comparison to prevent timing side-channel attacks.

Double-Vote Prevention & Database Idempotency

Mathematical Idempotency
The Challenge & Mathematical Solution

• The Vulnerability: Fast repeated clicks or network retries could artificially inflate vote counts and distort administrative triage.

• The Two-Layer Shield:

1. Database Layer: Composite key enforces that the pair (submission_id, student_id) can appear only once in the entire database.

2. Application Layer: Java toggle logic provides a seamless toggle-on / toggle-off user experience.

Anti-Vote Manipulation
SQL Composite Constraint Definition
CREATE TABLE submission_hype (
  hype_id SERIAL PRIMARY KEY,
  submission_id INT REFERENCES submissions,
  student_id INT REFERENCES users,
  CONSTRAINT uq_submission_student
    UNIQUE (submission_id, student_id)
);

Even if duplicate network requests arrive concurrently, the database constraint rejects the second insert without data corruption.
